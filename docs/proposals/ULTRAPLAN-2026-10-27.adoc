== Verdict in one page

*What this repository is.* 392 tracked files, 0 lines of reconciliation
code. 118 `.a2ml` files in a format the estate retired (D99, D269c, D312,
D313) and 0 `.deed`. An ABI/FFI seam copied from the template in which the
Idris2 side binds `rsr_init`/`librsr` and the Zig side exports
`recon_silly_ation_init`, with a `Result` enum of four cases on one side and
five on the other. A roadmap that, until this branch, read "YOUR Template
Repo Roadmap". Eleven workflows red on `main` as of 2026-10-25. One open
issue, already answered by the owner on 2026-09-30 and not closed.

*Why that is the interesting part.* The repository's stated purpose is to
find "small-looking contradictions that make a repository's documentation,
history, metadata, and attribution disagree". Its own scaffolding has
generated, without anyone writing a line of product code, one instance of
nearly every inconsistency class it names: an unpropagated rename (template
name in `ECOSYSTEM.a2ml`), dangling references (`AFFIRMATION.adoc`,
`benches/`, `SPECIFICATION.md`), a completion claim that outruns evidence
(STATE says 20%; the 20% is the template), an attribution surface copied
verbatim, and two explanations that cannot both be true (ABI vs FFI). The
template did this to roughly three hundred minted repositories. *The product
is a template-drift reconciler before it is anything else*, and its market is
the estate.

*The design.* Treat each repository *fact* (name, purpose, licence, status,
symbol set, each link target, each contributor credit, each spelling policy)
as a variable with a finite domain of *observed values*, one per surface that
states it, each tagged with its evidence span and input hash. Treat each
"these must agree" relation as a constraint. Run propagation to a fixpoint.
Where the network has a declared *authority* for the fact (the deed, the
filesystem, the licence policy), narrowing the other surfaces to the
authoritative value is a *proposal* with provenance. Where it has none, an
empty domain is a *finding for review*. That is D152 as a theorem shape, not
a rule: reconciliation ends exactly where no authority licenses the
narrowing. The estate already has this machine designed twice, as
squeakwell's "cross-modal constraint convergence" over database modalities
and as VeriSimDB's consonance loop over an octad of witnesses. This
repository is the third instance, over documents, and should share the
vocabulary and, in time, the core.

*What to build first.* Not ForthWall. Rules in v0.1 are constraints as data,
not programs; a VM is scope for a rule that needs computation, and no such
rule is in the inconsistency list. Build the extractors, the constraint
network, the findings bus in pons-asinorum's evidence-class shape, and the
falsifier corpora, and point it at this repository. The first green run is
the one that reports the eleven findings in <<corpus>>.

*The recommended arm* for the owner's three open decisions is in
<<decisions>>: Rust core verified with Creusot plus Idris2 for the finding
and patch IR (the estate's mapped provers), the VeriSimDB *model* adopted now
behind a trait and its *service* adopted when it is reachable, and
ForthWall deferred with a written trigger condition.

[#design]
== 4. Core design: constraint propagation over surfaces

=== 4.1 The model

* A *surface* is a file or API view with an extractor `view_i : Repo → Partial(Facts)`: README, deed (or legacy A2ML), CHANGELOG, GitHub metadata, `abi.ipkg`, Zig exports, workflow names, every hyperlink.
* A *fact slot* is a variable `x_f` for a fact `f` (canonical name, purpose sentence, licence, status, completion, each exported symbol, each link target, each contributor credit on each file, spelling policy).
* The *domain* of `x_f` is the finite set of observed values `{(v, surface, span, sha256(surface))}`. The domain is never widened by the tool.
* A *constraint* is a relation over slots: equality through a declared comparison map (`agree_modulo(nfc ∘ casefold)`), existence (`link target ∈ filesystem`), bijection (`idris_exports ≅ zig_exports`), order (`completion ≤ evidence_count/required_count`), or absence of path (attribution locality).
* An *authority* is a designated surface for a slot: the deed for identity, the filesystem for paths, the licence policy for SPDX, `git log` for authorship. Authorities come from the deed's `(anchor)` clause, never from the tool.

=== 4.2 Propagation and the D152 boundary

Run generalised arc consistency to a fixpoint. Domains only shrink, so the
run terminates and re-running on the result changes nothing: the
*idempotence* and *monotonicity* obligations are properties of the solver,
not of each rule. Three outcomes per slot:

[cols="1,2,2",options="header"]
|===
|Domain after propagation |Meaning |Output

|singleton |all surfaces agree (modulo declared maps) |nothing, or an `INFO` record of the agreement with its spans
|non-singleton, authority present |surfaces disagree and one is designated |*proposal*: narrow the others to the authority's value, with every span, every hash, and the authority named
|non-singleton, no authority |genuine contradiction |*finding for review*; the tool has no licence to pick
|===

This is D152 made structural. "Reconciliation stops where a change would
alter meaning" becomes: a proposal exists only along an authority edge, and
authority edges are declared only for meaning-preserving relations. The
comparison map may fold case and Unicode; the *proposal* never writes the
folded form, it writes the authority's literal value. In echo-types terms,
comparison is on the image of the normalising map and the proposal reports
the fibre instead of collapsing it. That is the whole of clause 4 for this
component, and it is a statement about the solver, so it is provable once.

=== 4.3 What the constraint language must not be

Rules as *data* (a constraint table in a `.k9.ncl` contract, validated by
`k9-validate.sh`), not as programs. A rule that needs computation beyond
equality-through-map, existence, bijection, order and path-absence is the
trigger condition for ForthWall, and the first such rule should be written
down before any VM is. None of the eleven classes in <<corpus>> needs one.

=== 4.4 Findings and patches on the wire

Adopt pons-asinorum's finding shape rather than invent one: `rule_id`
stamped by the engine, `tier → evidence class` derived (never set by the
rule), `severity`, `location` in UTF-16 columns, `evidence_note`,
`counter_condition`. Add two fields pons does not have: `authority`
(nullable) and `proposal` (nullable patch with the authority's literal
value). Evidence classes map cleanly: a link-existence check is `DATAFLOW`
(the filesystem is the ground truth), an ABI/FFI bijection is `PROTOCOL`,
a spelling-policy inference without a declared slot is `HEURISTIC`, and
anything an LLM suggested is `SPECULATIVE` and cannot gate. SARIF 2.1.0 out
for PRs, I-JSON/JCS (D306) for the record, so the output lands on the one
findings bus the Kautz-ladder plan is asking for.

[#value]
== 9. Value, speculated honestly

*The negative case.* A reconciler for prose is a near-neighbour of a linter,
and linters for prose have a poor record: they fire on style, humans mute
them, and the mute list grows. If this tool is judged by "findings per
repository" it will be muted within a month.

*The positive case, and it is specific.* The estate has one template and
roughly three hundred children of it. The template's self-description is a
constraint network with *no propagation*: when the template changes a path,
renames a file, fixes a gate, or retires a format, every child keeps the old
value until a human notices (the Kautz plan's own census found 43 `.md→.adoc`
renames never propagated in one repository). That is not style; it is
provenance decay with a known authority (the template's current file) and a
known relation (lineage). A tool that reports *only* that, with evidence,
at `:review`, fed back to the template rather than to the children, would
pay for itself on the first run, because the eleven rows in <<corpus>> are
the same eleven rows in most of the three hundred.

*What makes it defensible rather than a linter.* Three things no linter has:
an authority model (so it can say *why* one value wins), a fibre-preserving
comparison (so it can say two surfaces agree without rewriting either), and
a refusal class (so it says "cannot pick" instead of guessing). Those are
D152, echo-types and VCL-UT's admissibility, respectively, and they are what
the owner has been building elsewhere. The tool is small; the vocabulary it
inherits is not.

*Learning from the mess.* Scaffolding before substance produces repositories
whose honesty documents are themselves dishonest, not through anyone's
intent but because a copied "proof and delivery status" section is a claim
about a different repository. The remedy is not more scaffolding; it is one
machine-readable authority (the deed) and a propagator that reads it. Second
lesson: a gate that cannot fail is worse than no gate (row 9, and the
template's `check-proofs.sh` header says the same). Every gate added in W0
is to be watched failing first. Third: the template shipped an ABI and an
FFI that do not agree, under a README saying they are proven to; the
cross-domain check that would have caught it is the first thing this tool
should run on itself.
